# /cronjob-doc — 排程文件撰寫

撰寫排程文件 SOP / Checklist

## 0. 前置確認（開始前一定要完成）

- 已確認排程名稱
- 已確認排程是否已存在（新建 / 修改）

**完成標準**：

> 我能清楚知道「這份文件在描述哪一支排程」。

---

## 1. 排程目的（Why）

- 已說明此排程解決的問題
- 已說明若沒有此排程會發生什麼事
- 未包含任何實作細節或程式語言
- 非技術人員可理解內容

**完成標準**：

> 任何人都能回答：「為什麼要跑這支排程？」

---

## 2. 排程頻率 / 執行時間（When）

- 已填寫執行頻率（一次性 / 每日 / 每小時…）
- 已填寫實際執行時間
- 已標註時區
- 已說明是否可手動觸發
- 已標註是否為低流量時段

**完成標準**：

> 維運人員知道「它什麼時候會動、能不能重跑」。

---

## 3. 程式流程（How）

- 流程以「步驟」描述
- 未出現 function / class / SQL 名稱
- 已包含成功與失敗處理分支
- 流程順序與實際執行一致
- 不超過一頁（避免變成 code）

**完成標準**：

> Backend 不看程式碼也能理解邏輯。

---

## 4. log 紀錄（Traceability）

- 已定義 INFO log 內容
- 已定義 ERROR log 內容
- 已包含排程名稱與資料識別欄位
- 已說明 log 儲存位置
- 已說明 log 保留期限

**完成標準**：

> 出問題時知道「去哪查、查什麼」。

---

## 5. 對資料表欄位的影響（Data Impact）

- 已列出所有會被存取的資料表
- 已標註每個欄位的操作行為（SELECT / INSERT / UPDATE）
- 已說明異動目的
- 已確認是否有 DELETE 或不可逆操作
- 已確認不影響其他排程

**完成標準**：

> DB Reviewer 能快速評估風險。

---

## 6. 資料流（Data Flow）

- 已標註資料來源
- 已描述處理過程
- 已標註資料輸出位置
- 已說明是否跨系統
- 流向單一、清楚、不循環

**完成標準**：

> 一眼看懂資料怎麼走。

---

## 7. 注意事項（Risk & Operation）

- 已說明是否可安全重跑（idempotent）
- 已標註可能失敗情境
- 已說明效能或資料量風險
- 已標註操作限制
- 已附上維運建議

**完成標準**：

> 接手的人不會踩雷。

---

## 8. 最終檢查（Before Close）

- 文件不需參考程式碼即可理解
- 文件內容與實際邏輯一致
- 無未說明的資料異動
- 適合交接、審查與上線前檢視

**完成標準**：

> 這份文件可以獨立存在。
