# Nielsen 10 大啟發式原則 × Vue 3 實作對應

| # | 原則 | 核心問題 | Vue 3 實作對應 | 常見違反 |
|---|------|----------|----------------|---------|
| 1 | **系統狀態可見性** | 用戶知道發生了什麼嗎？ | `isLoading` / `isError` Skeleton、進度條、步驟指示器 | 沒有 Loading 狀態，直接顯示空白 |
| 2 | **系統與現實世界對應** | 語言是用戶的語言嗎？ | 錯誤訊息用業務語言，非 HTTP code | 顯示「Error 422」而非「手機號碼格式不正確」 |
| 3 | **用戶控制與自由** | 用戶可以「後退」嗎？ | `router.back()`、確認 Modal、撤銷 Toast | 刪除後無法復原、送出後無法修改 |
| 4 | **一致性與標準** | 相同的事物長得一樣嗎？ | 統一使用 Design Token、共用元件庫 | 同功能按鈕在不同頁面顏色不同 |
| 5 | **錯誤預防** | 系統阻止了錯誤發生嗎？ | disabled 狀態、Inline Validation、確認步驟 | 允許送出未填完的必填欄位 |
| 6 | **識別勝於回憶** | 選項是可見的嗎？ | Dropdown、Autocomplete、麵包屑 | 要用戶記住上一步填了什麼 |
| 7 | **彈性與效率** | 進階用戶有捷徑嗎？ | 鍵盤快捷鍵、批次操作、搜尋篩選 | 每次都要點 5 步才能完成常用操作 |
| 8 | **美觀與簡約設計** | 畫面有不必要的資訊嗎？ | 奧卡姆剃刀、Progressive Disclosure | 把所有欄位都塞在第一頁 |
| 9 | **協助用戶識別、診斷、修復錯誤** | 錯誤訊息有用嗎？ | 錯誤位置標紅 + 訊息 + 修正建議 | 只顯示「發生錯誤，請稍後再試」 |
| 10 | **說明文件與協助** | 有需要時找得到幫助嗎？ | Tooltip、說明文字、Help 連結 | 專業術語無任何說明 |

## 評估輸出格式

執行 CASE D 全面 UX Review 時，輸出以下格式：

```markdown
## UX Heuristics 評估報告

| 原則 | 評分 | 問題描述 | 嚴重度 | 建議修正 |
|------|------|----------|--------|---------|
| #1 系統狀態可見性 | ✅ 通過 | - | - | - |
| #3 用戶控制與自由 | ❌ 違反 | 刪除操作無確認 | Critical | 加入確認 Modal |
| #9 錯誤診斷與修復 | ⚠️ 待改善 | 訊息語意模糊 | Major | 改寫為業務語言 |

嚴重度定義：
- Critical：用戶無法完成核心任務
- Major：用戶需要額外努力才能完成
- Minor：影響體驗但不阻礙完成
```
