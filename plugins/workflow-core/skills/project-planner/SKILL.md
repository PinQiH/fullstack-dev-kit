# 專案規劃師

把專案拆成可估時、可指派、可驗收的任務，並標出相依關係、里程碑與風險。

## 規劃流程

### 1. **定義成功**
- 最終目標是什麼？
- 成功標準有哪些？
- 如何定義「已完成」？
- 有哪些限制 (時間、預算、資源)？

### 2. **辨識交付物**
- 主要的產出物有哪些？
- 哪些里程碑標誌著進度？
- 存在哪些相依性？
- 哪些東西是可以平行處理的？

### 3. **拆解任務**
- 每個任務規模大約：2-8 小時的工作量
- 具備明確的「完成」標準
- 可被指派給單一負責人
- 可供測試 / 可驗證完成度

### 4. **繪製相依性藍圖**
- 什麼必須先做完？
- 什麼可以平行進行？
- 要徑上的項目是什麼？
- 瓶頸卡在哪裡？

### 5. **估期與緩衝**
- 想出最佳、最有可能、最壞的情境
- 增加 20-30% 的緩衝時間來應對未知因素
- 將 Code Review / 測試的時間考量進去
- 包含風險的應急措施

### 6. **指派與追蹤**
- 誰負責哪個任務？
- 需要什麼樣的技能？
- 如何追蹤進度？
- 何時安排進度檢查點？

## 任務規模估算指南

**太大** (>2 個工作天):
- 需再往下拆分成子任務
- 難以精準估算
- 難以追蹤進度
- 阻礙其他工作過久

**剛好** (2-8 小時):
- 明確的交付物
- 一人即可獨自完成
- 每天都能看見實際進展
- 容易估算 

**太小** (<1 小時):
- 可能過度規劃了
- 管理成本 / 溝通成本太高
- 建議將相關的微小任務整併

## 估算技術

### 三點估算法
```
樂觀（O）：最佳情境
最可能（M）：預期情境
悲觀（P）：最壞情境

預期時間 = (O + 4M + P) / 6
```

### T-Shirt 尺寸估算法
- **XS**: < 2 小時
- **S**: 2-4 小時
- **M**: 4-8 小時 (1 個工作天)
- **L**: 2-3 個工作天
- **XL**: 1 週

*把任何大於 XL 的任務再往下拆分*
